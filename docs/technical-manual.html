How htmlbin actually runs

One Cloudflare Worker, one D1 database, one KV namespace. An agent publishes a self-contained HTML document and receives a stable public URL. A human signs in with GitHub once, during device-code verification. After that the agent calls the API with a bearer token.

This manual is grounded in the Worker source at commit ac00be7. The protocol descriptor in src/onboard.ts is the contract agents are told to trust. Where another surface (llms.txt, the OpenAPI document, the operating manuals) says something the handlers do not do, the handler wins, and section 20 lists the difference. This file is an engineering document in the repo. The Worker does not serve it.

01Scope

In scope: the Worker in this repository, its D1 schema, its KV layout, the HTTP contract, and the way HTML is stored and served.

In scope with the HTTP API: POST /mcp, a stateless Streamable HTTP door. It checks the same Authorization: Bearer hb_… token and calls the existing drop routes. It does not open a browser login and it does not publish OAuth metadata.

Product constraints that the code is built around, from the operating manuals: no signup, login, email, dashboard, or account page on the public site; GitHub OAuth exists only inside device-code verification; HTML is stored as posted; the deploy path is a pull request, a preview URL, approval, then merge to main.

Sources: AGENTS.md, CLAUDE.md, src/onboard.ts, src/errors.ts

02What it is

A drop is one HTML artifact. The public URL is https://htmlbin.aesir.works/p/<slug>. The slug does not change when the HTML changes. Each upload of new HTML is a version. Metadata (title, description, a string-to-string tag map, an optional passcode) hangs off the drop. An optional context string hangs off a single version.

The body lives in KV. Everything you can list, authorize, or count lives in D1. The viewer page is chrome around an iframe. The iframe loads /p/<slug>/raw, which is the stored HTML plus a small mobile safety style.

Sources: schema.sql, src/types.ts, src/drops.ts, src/index.ts

03Runtime

The program is a Hono app in src/index.ts. Wrangler name htmlbin, compatibility_date 2025-04-01, compatibility_flags = ["nodejs_compat"]. Application code hashes and signs with Web Crypto, not Node crypto. The Worker is bound to the custom domain htmlbin.aesir.works. Generated links use PUBLIC_URL, which is https://htmlbin.aesir.works.

04Request pipeline

Two middlewares wrap every route. The security middleware calls next() first, then sets headers on the way out. The pepper middleware rejects the request before the route when the secret is missing or shorter than 32 characters.

There is no CORS middleware. A browser page on another origin cannot call the API with the user's token. Adding CORS is a product decision, not a missing header.

Read routes that are registered with app.on(["GET", "HEAD"], …) answer HEAD. Mutations are method-specific. Unknown paths render the HTML 404 in notFoundHtml(), except API-shaped misses that call apiError() themselves (a bad pattern filename does).

Sources: src/index.ts (both app.use("*") blocks and app.notFound)

05Identifiers and crypto

All randomness comes from crypto.getRandomValues. Base62 strings are built by taking each random byte modulo 62. The alphabet is 0-9A-Za-z. Human codes use a 32-character alphabet that omits I, O, 0, and 1.

Identifier formats, from src/crypto.ts and src/slug.ts
ThingShapeNotes
Slug9 chars base62generateSlug ignores the title argument. Accepted slugs are /^[A-Za-z0-9]{6,12}$/ so older lengths still resolve. Collision check retries up to 5 times.
User idu_ + 16 base62Primary key of users. Stable across tokens and devices.
API tokenhb_ + 40 base62Shown to the agent once. Stored as SHA-256(pepper :: token) hex.
Poll token48 base62Query secret for GET /api/auth/poll. Not an API token.
Verify codeXXXX-XXXXUppercase human alphabet. 10 minute TTL. Also the OAuth state.
Token id12 hex charssubstr(token_hash, 1, 12). This is what DELETE /api/tokens/:id accepts. It is not a prefix of the plaintext token.

Hashes and cookies

  • API tokens: SHA-256 of the UTF-8 string ${pepper}::${token}, hex. Lookup requires revoked_at IS NULL.
  • Passcodes: PBKDF2-HMAC-SHA-256, 100,000 iterations, 16-byte salt, 256-bit output, both salt and hash stored as hex in password_salt and password_hash. Comparison is a constant-time XOR over the hex strings.
  • Unlock cookie name: wu_<slug>. Value: ${slug}.${expEpochMs}.${hmac}. HMAC-SHA-256 over the string ${slug}|${exp}, key TOKEN_PEPPER. Path=/p/<slug>, HttpOnly, Secure, SameSite=Lax, Max-Age 86400. Verification rejects a mismatched slug, a non-numeric expiry, an expiry before Date.now(), or a bad MAC.

The same pepper is the token salt and the cookie key. The HTML body is not encrypted with it. A passcode does not wrap the KV object.

Sources: src/crypto.ts, src/slug.ts, src/auth.ts, src/index.ts unlock handlers

06Data model

schema.sql is the idempotent definition for a fresh database. Databases that already exist take migrations/0001-github-oauth.sql (GitHub columns and the partial unique index) and migrations/0002-drop-metadata.sql (the metadata column). Timestamps are Unix epoch milliseconds from Date.now().

users.github_user_id is nullable so tokens minted before OAuth still resolve. The unique index is partial: WHERE github_user_id IS NOT NULL. New accounts always set it. display_name on create is the GitHub login.

drops.metadata is a JSON text column, default {}. The public viewer never selects it into the HTML. password_hash and password_salt are the internal names of the passcode. The API field is passcode, and the JSON drop uses locked: true|false instead of returning the hash.

versions.context is optional text, at most 64 KiB of UTF-8. It is per version. Replacing HTML with PUT stores a new context on the new version only. The owner API returns the context string from GET /api/drops/:slug/v/:n. The version list returns has_context and omits the body.

Sources: schema.sql, migrations/0001-github-oauth.sql, migrations/0002-drop-metadata.sql, src/db.ts, src/github-oauth.ts

07Authentication

The flow is an OAuth device-code dance. The agent never sends the human to a signup form. The only human step is /verify, which is a GitHub sign-in bound to a verification code. One GitHub numeric id maps to one htmlbin user. A second machine, signed in with the same GitHub account, receives a new token on the same user_id. Quotas and drops stay with that user.

GitHub is asked for scope read:user only. The callback reads id and login from https://api.github.com/user. The verification code is the OAuth state. The callback re-reads the verification row and refuses it unless status is still pending and expires_at is in the future.

Poll semantics

POST /api/auth/start accepts an optional JSON body. label, when it is a string, is sliced to 64 characters and later stored on the token row. A missing or non-JSON body is fine. The response is:

{
  "code": "AB3K-7NPQ",
  "verification_url": "https://htmlbin.aesir.works/verify?code=AB3K-7NPQ",
  "poll_token": "<48 base62 chars>",
  "expires_in": 600,
  "poll_interval": 2
}

GET /api/auth/poll?token= returns HTTP 200 for every recognized poll, including pending, expired, and already-claimed. The body is { "status": "pending" | "expired" | "claimed" }. The first time the row is verified and api_token is still set, the handler nulls the column, sets status to claimed, and returns { "status": "verified", "api_token", "user_id" }. A missing poll token is 400 token_required. An unknown token is 404 not_found.

Expiry is applied when a poll sees status = pending and expires_at in the past. There is no background sweeper. A verified row that nobody polls keeps the plaintext API token in verifications.api_token. A pending row stays pending until something polls it.

Start is limited to 10 requests per minute per CF-Connecting-IP (bucket auth:start:<ip>). Poll is limited to 60 per minute per poll token (auth:poll:<token>). The callback is limited to 20 per minute per IP (gh:cb:<ip>) and, on failure, renders the verify HTML page rather than apiError JSON. GitHub exchange or /user failure is HTTP 502 HTML.

Bearer middleware

authMiddleware is mounted on /drops, /drops/*, /me, /tokens, and /tokens/* under the /api prefix. The header must match Bearer hb_ plus base62. Anything else is 401 unauthorized. An unknown or revoked hash is 401 invalid_token. On success the context user is { id, tokenHash }. last_used_at is updated inside waitUntil, so the request does not wait for that write.

Agents are told to read the token from ./.htmlbin/token, then HTMLBIN_TOKEN, then ~/.config/htmlbin/token. The Worker does not read those paths. It only sees the Authorization header.

Sources: src/auth.ts, src/github-oauth.ts, src/onboard.ts auth.steps, src/db.ts getUserByTokenHash

08Drop API

Mutating endpoints that change a drop return the full serialized drop. The exception is DELETE /api/drops/:slug, which returns 204 with an empty body. DELETE /api/tokens/:id is also 204. Field names are snake_case. List-of-drops is the only list that wraps { data, pagination }. GET /api/tokens returns a bare array, including revoked rows.

{
  "slug": "aB3xK7gPq",
  "title": "My page",
  "description": "",
  "url": "https://htmlbin.aesir.works/p/aB3xK7gPq",
  "raw_url": "https://htmlbin.aesir.works/p/aB3xK7gPq/raw",
  "locked": false,
  "latest_version": 1,
  "view_count": 0,
  "metadata": {},
  "created_at": 0,
  "updated_at": 0
}

metadata is always present. Malformed JSON in the column degrades to {} inside parseMetadata(). created_at and updated_at are epoch milliseconds.

Create, replace, patch

On create, the handler writes KV html:<slug>:v1 first, then a D1 batch that inserts the drop and version 1. On PUT it writes html:<slug>:v<next> first, then a batch that inserts the version row and updates latest_version. KV and D1 are not one transaction. A D1 failure after the KV put leaves an unreferenced object.

Title and description limits use JavaScript string length: 200 and 500. HTML and context limits use UTF-8 byte length from TextEncoder: 2,097,152 and 65,536. Empty title is title_required. Empty HTML on create is html_required. Non-string JSON values for string fields are 400 invalid_arg.

PUT and PATCH treat omitted title, description, and metadata as “leave the column alone” via COALESCE. Metadata replace-whole: omit the field to keep it, send {} to clear it, send an object to overwrite the map. null is rejected.

Ownership checks return 404 not_found when the slug does not exist and 403 forbidden when it exists for another user. A slug that fails isValidSlug is 400 invalid_slug and is not looked up.

Versions

The next version number is latest_version + 1. Holes are not reused. The cap check is latest_version >= 200, so deleting a middle version does not make room for version 201. Deleting the current head rewinds latest_version to the maximum remaining version number, and a later PUT can occupy that head number again.

DELETE /api/drops/:slug/v/:n refuses when only one version row remains (409 last_version_cannot_be_deleted). Otherwise it deletes the KV key, deletes the version row, and if that row was the head, rewinds latest_version. The response is the updated drop.

DELETE /api/drops/:slug deletes KV keys from version 1 through the current latest_version inclusive, then deletes version rows and the drop row in one D1 batch. A key whose number is above the current head is not visited by that loop. The head-delete path deletes that key before it rewinds the counter, so the ordinary case is covered.

Reads for the owner

  • GET /api/me returns user_id, created_at, drop_count, and the current token (id, label, created_at, last_used_at). It does not return the GitHub login.
  • GET /api/drops filters to the caller. Query: page (default 1), pageSize (default 50, max 200), sortBy (created_at, updated_at, view_count), sortOrder (asc or desc). The ORDER BY column is chosen from that whitelist.
  • GET /api/drops/:slug/versions returns version, size, has_context, created_at, is_latest. No HTML.
  • GET /api/drops/:slug/v/:n adds the context string. Unknown version: 404 version_not_found.

There is no server upsert. The advertised recipe is list-by-metadata, then PUT if a row matches, otherwise POST. The MCP tools for that recipe are list_drops, then update_drop or create_drop. Two parallel creators can both observe an empty list and both POST. The API does not serialize that.

Sources: src/drops.ts, src/db.ts listDropsByUser, src/onboard.ts publish / iterate / list_my_drops

09Public rendering

GET /p/:slug is the human page. GET /p/:slug/raw is the document. The page loads the document in an iframe. The homepage embeds one real drop the same way: SHOWCASE_SLUG is the constant ztx4J9P in src/views/landing.ts, and the iframe source is /p/ztx4J9P/raw. Raw responses do not increment view_count, so that embed does not count as a view.

?v=N pins the viewer and the raw route when N is an integer from 1 through latest_version. Any other value is ignored and the latest version is served. The check does not confirm that the version row still exists. A deleted middle version in that range still selects that number; raw then 404s because the KV key is gone, while the chrome page still renders.

The viewer iframe is sandbox="allow-scripts allow-forms allow-modals allow-downloads". allow-same-origin is absent, so scripts in the drop run in an opaque origin. The HTTP request that loads /raw is still a same-site request and still carries the unlock cookie, which is how a locked drop renders inside the frame after unlock.

The document title and og:title are <title trimmed to 15 words> - <slug> - <host>. A non-latest pin shows a banner. If the current version has context, a button reveals it in the chrome. The raw link opens the same version.

Author line: getDropWithAuthor left-joins users.github_login. A login becomes a link to https://github.com/<login>. A null login (legacy accounts) renders as “an agent”.

view_count increments on the viewer route via waitUntil, including requests that receive the gate. Public viewer responses send Cache-Control: public, max-age=60, s-maxage=900, so a cache hit does not run the handler and does not bump the counter. Locked viewer responses send private, no-store. Raw sends public, max-age=60, s-maxage=300, or private, no-store when locked, plus X-Robots-Tag: noindex. The viewer HTML also sets <meta name="robots" content="noindex">.

Safety net on raw HTML

injectMobileSafetyNet() runs on every raw response. If no viewport meta is present it inserts <meta name="viewport" content="width=device-width, initial-scale=1"> after <head>, else after <html>, else at the start. It appends one style element before </head>, else before <body>, else at the start:

html,body{max-width:100vw;overflow-x:clip}
img,svg{max-width:100%;height:auto}
video,iframe{max-width:100%}
pre,table{max-width:100%}
pre{overflow-x:auto}

The style tag carries data-htmlbin-safety. There is no opt-out flag. overflow-x: clip is intentional so the rule does not create a scroll container.

Sources: src/index.ts viewer, raw, unlock; src/views/viewer.ts; src/views/landing.ts; src/safety-net.ts; src/db.ts bumpViewCount

10Passcode gate

A passcode is a share gate. The KV object stays plaintext. Readers who do not present a valid wu_<slug> cookie see the gate on /p/:slug and are redirected from /p/:slug/raw back to that page. Unlock is POST /p/:slug/unlock with form field passcode. A match sets the cookie and redirects to the viewer. A miss re-renders the gate. Lock is POST /p/:slug/lock, which expires the cookie. The lock route does not check a CSRF token; its only effect is the caller’s own cookie.

The gate input is type="text" with autocomplete="off". Masking is CSS -webkit-text-security: disc and the standard text-security: disc, with a show/hide control that toggles those properties. The placeholder is not masked.

POST /api/drops/:slug/passcode with a string shorter than 4 characters returns 400 passcode_too_short. An empty string clears both hash columns. A missing or non-string passcode is 400 passcode_required. The create handler is different: any non-empty passcode string is hashed and stored, and validateCreateBody() does not apply the length floor. The onboard descriptor and the OpenAPI document both describe the create field as minimum length 4.

Sources: src/index.ts, src/drops.ts, src/views/viewer.ts passcodeGatePage, src/styles.ts .gate-input, src/onboard.ts

11Metadata

Metadata is an owner-side tag map. Keys match /^[a-z0-9_]([a-z0-9_.-]{0,62}[a-z0-9_])?$/i, at most 64 characters. Values are strings, at most 256 characters. At most 10 keys. Nested objects, arrays, and non-strings are invalid_arg. No key is reserved.

Filters are query keys metadata.<key>=<value>, ANDed. The SQL is json_extract(metadata, ?) = ? with the bound path $.<key> and the bound value. The filter key is checked with the same regex before it is bound. There is no secondary index. The user_id predicate is what keeps the scan small.

The map is drop-level. Versions do not snapshot it. Context is the per-version text channel.

Sources: src/drops.ts validateMetadata, src/db.ts listDropsByUser, migrations/0002-drop-metadata.sql

12Limits

rateLimit() in src/db.ts is a fixed window in D1. The window starts at floor(now / windowMs) * windowMs, so a “day” is 86,400,000 ms aligned to the Unix epoch, not a calendar day in a local timezone, and not a rolling 24 hours from the first hit. The check reads the row, then inserts or updates. Two overlapping requests can both pass the check. The comment in db.ts calls it best-effort.

When the limiter refuses, retryAfter is the whole seconds until the window ends, at least 1. Callers that use it set both the Retry-After header and details.retry_after_seconds.

13Errors

API failures go through apiError():

{
  "error": {
    "code": "html_too_large",
    "message": "HTML exceeds 2097152 bytes.",
    "details": { "max_bytes": 2097152 }
  }
}

details is omitted when the caller does not pass it. Agents are told to switch on code. The legal codes are the ErrorCode union. Statuses used by that helper are 400, 401, 403, 404, 409, 413, 422, 429, 500, and 503. Not every code uses every status. Quota failures that are “too many” use 429. last_version_cannot_be_deleted uses 409.

Two JSON failures do not use this envelope. Landing markdown, when Workers AI throws, returns 503 { "error": "markdown_unavailable", "detail": "…" }. A pepper failure does use apiError with server_misconfigured.

Public HTML routes (viewer, verify, favicon misses, the app 404) return HTML. GitHub start and callback errors return the verify page with an error string and statuses 400, 404, 409, 410, 429, or 502.

14Discoverability

These routes are one contract. buildOnboardJson() is the protocol. src/discoverability.ts renders robots, llms.txt, the sitemap, the agent card, the OpenAPI 3.1 document, and the Link header on GET /. Skill bytes come from src/skill.ts. Pattern bytes come from src/patterns.ts. The OpenAPI document is handwritten in openApiSpec(). It is not generated from the route table.

GET /api/onboard returns JSON. Markdown is served when Accept contains text/markdown, or when ?format=md. Responses send Vary: Accept. The landing page uses a stricter check: markdown wins only when text/markdown appears and either text/html is absent or markdown appears first.

The sitemap lists /, /api/onboard, /llms.txt, and /openapi.json. lastmod is the UTC date at request time. Drop URLs are not included. robots.txt allows the major AI crawlers and disallows /api/auth/ and /verify.

GET /.well-known/api-catalog is RFC 9727 application/linkset+json. Its status link points at the agent card. There is no separate health route.

GET /.well-known/security.txt is RFC 9116. Contact security@htmlbin.aesir.works. The expires value in the source is 2027-05-10T00:00:00.000Z.

The agent-skills index follows the discovery schema 0.2.0. One skill, name htmlbin, URL /.well-known/agent-skills/htmlbin/SKILL.md, digest sha256: of the bundled markdown. POST /mcp is advertised from the same discoverability surfaces.

Sources: src/discoverability.ts, src/onboard.ts, src/skill.ts getSkillDigest / agentSkillsIndex, src/index.ts route table

15Patterns and skills

Patterns are markdown the agent reads before it writes HTML. The Worker does not render them into a drop and does not validate uploaded HTML against them. The resolution order the skill teaches is: ./.htmlbin/patterns/*.md, then ~/.config/htmlbin/patterns/*.md, then GET /.well-known/patterns/<name>.md. The index is GET /.well-known/patterns/index.json.

Human-readable copies live in patterns/. The bytes the Worker serves are string constants in src/patterns.ts, because Wrangler 4 has been unreliable at importing non-JS files from outside src/. The same split exists for the skill: skills/htmlbin/SKILL.md and the template literal in src/skill.ts.

Official names and the triggers stored on PatternMeta:

  • pr-explainer — explain a pull request.
  • summary-roundup — threads, weekly status, incident timelines.
  • plan-spec-explainer — a plan or spec.
  • session-explainer — an agent session. This one is prescriptive. Front matter sets brand_sensing: true, brand_scope: colors-only, and template: session-explainer.template.html. The index adds template_url. The template is served as text/plain so edge HTML rewriting does not inject a script into the skeleton.

brand_scope and template are extra front-matter keys. brand_sensing stays a boolean. Unknown keys are ignored, which is why the narrower rule is a second key.

Sources: src/patterns.ts, patterns/session-explainer.md, src/skill.ts, src/index.ts pattern routes

16Fonts and OG images

Page chrome uses Geist and Geist Mono. The woff2 files in assets/fonts/ are base64-inlined into src/fonts-data.ts by scripts/build-fonts.mjs. src/fonts.ts decodes them once and GET /fonts/:name serves font/woff2 with Cache-Control: public, max-age=31536000, immutable. CSS is also inlined into HTML via STYLE_INLINE. GET /style.css still exists, with the same immutable cache, and STYLE_HREF appends ?v=<hash of the CSS>.

Social cards are PNG, 1200×630, drawn by satori/standalone and rasterized by @resvg/resvg-wasm. Both WASM modules ship as precompiled WebAssembly.Module values through [[rules]] type = "CompiledWasm", because Workers reject WebAssembly.compile. The satori tree is built with small element helpers in src/views/og-png.ts. satori-html is listed in package.json and is not imported.

OG fonts are a different set from the page fonts: Geist 500, Geist Mono 400, and Geist Mono 500, fetched from jsDelivr @fontsource on a cold isolate, packed, and stored at KV og-fonts:v1 for 30 days. The put is not awaited.

GET /og.png caches og-png:landing:v3 for 7 days. GET /p/:slug/og.png caches og-png:<slug>:v<latest_version>:r3 for 30 days. Both responses use Cache-Control: public, max-age=300, s-maxage=86400 and X-Og-Cache: hit|miss. If render throws, the handler logs and redirects to the SVG sibling. Nothing in src/index.ts reads a debug query. SVG variants are built in src/views/og-image.ts and do not use the WASM path.

/sentry.js returns a comment when SENTRY_DSN is unset. When it is set, the script inserts https://js.sentry-cdn.com/<public key>.min.js and calls Sentry.init with tracesSampleRate: 0.1. The loader is referenced from the landing page, the verify page, and the viewer, including the gate. It is not injected into raw drop HTML by the Worker.

Sources: src/fonts.ts, src/views/og-png.ts, src/views/og-image.ts, src/index.ts font and OG routes, wrangler.toml [[rules]]

17Security headers

Every response, after the handler returns:

  • Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
  • X-Content-Type-Options: nosniff
  • Referrer-Policy: strict-origin-when-cross-origin
  • Permissions-Policy disabling geolocation, camera, microphone, payment, and usb

For text/html, if the handler has not already set Content-Security-Policy, the middleware adds X-Frame-Options: SAMEORIGIN and a CSP: default-src 'self', images from 'self' data: and https:, styles 'self' 'unsafe-inline', fonts 'self', scripts 'self' 'unsafe-inline' plus https://static.cloudflareinsights.com, connect-src 'self', frame-src 'self', frame-ancestors 'none', base-uri 'none'. When SENTRY_DSN is set, script-src also allows js.sentry-cdn.com and browser.sentry-cdn.com, and connect-src allows https://*.ingest.sentry.io and https://*.ingest.us.sentry.io.

JSON and application/linkset+json get Content-Security-Policy: default-src 'none' when the handler did not set one.

Raw HTML sets its own policy, so the middleware leaves that CSP in place and does not add X-Frame-Options. The raw policy is frame-ancestors 'self'; base-uri 'none'; form-action 'self' https:. The raw handler also sets Referrer-Policy: no-referrer. The middleware runs after the handler and sets Referrer-Policy on every response, so the value that leaves the Worker is strict-origin-when-cross-origin. The CSP check is the one header the middleware refuses to overwrite.

Sources: src/index.ts security middleware and the raw response headers

18Operations

Local

npm run dev runs Wrangler through node node_modules/wrangler/bin/wrangler.js. The .bin shim is a regular file whose path math misses wrangler-dist, which is why the npm scripts invoke the bin path directly. Local D1 state lives under .wrangler/state/. Fresh schema: npm run db:apply:local. Incremental files in migrations/: npm run db:migrate:local. .dev.vars supplies the pepper and, in the example, GITHUB_CLIENT_ID=dev-mock.

npm run test:e2e runs scripts/agent-e2e.sh against BASE_URL, default http://localhost:8787. It walks discovery, device-code auth through the mock, CRUD, versions, context, passcodes, ownership, and cleanup. npm run typecheck is tsc --noEmit.

npm run dashboard serves a read-only UI on 127.0.0.1:5173 that shells out to wrangler d1 execute. It is not mounted on the Worker. npm run stats is the text snapshot of the same idea.

Deploy

.github/workflows/deploy.yml runs on push to main and on pull requests into main. It type-checks, runs npm audit --omit=dev --audit-level=high, then either wrangler deploy (push to main) or wrangler versions upload (pull request). The preview URL is scraped from the command output and posted as a sticky comment. Concurrency cancels a superseded pull-request run. A main deploy is not cancelled by a later run. Preview versions share production D1, KV, and AI bindings. The only GitHub secret the workflow reads is CLOUDFLARE_API_TOKEN.

Requests to htmlbin.aesir.works/api/* without a User-Agent are described in the operating manual as rejected by a Cloudflare ruleset with error 1010 before the Worker runs. That rule is not in this repository. Local Wrangler does not apply it.
